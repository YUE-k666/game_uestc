# 《重生之我在电子科大干后勤》游戏设计文档

## 一、基本信息

| 项目 | 内容 |
|------|------|
| 类型 | 校园后勤管理模拟 |
| 基调 | 策略硬核，注重数据和权衡 |
| 视角 | 2D 正交俯视角，像素风 |
| 引擎 | Godot 4 + GDScript |
| 语言 | 中文 |
| 目标平台 | 桌面端（Linux/Windows/macOS） |

## 二、玩家角色

有经验的校园后勤管理者。开局已有完整的基础设施（10+ 栋宿舍楼、5+ 个食堂、教学楼等），核心任务是**优化运营**，而非从零搭建。

## 三、时间系统

### 3.1 推进方式

实时推进，四档速度控制：暂停 / 正常 / 快进 / 极速。

### 3.2 每日时段（7 个时段）

| 时段 | 学生活动 | 建筑运营 |
|------|---------|---------|
| 早晨 | 起床、吃早餐 | 食堂早餐窗口开放，宿舍楼 |
| 上午 | 上课 | 教学楼活跃，食堂关闭 |
| 中午 | 吃午餐 | 食堂午餐窗口开放 |
| 下午 | 上课 | 教学楼活跃，体育馆可开放 |
| 傍晚 | 吃晚餐、自由活动 | 食堂晚餐窗口开放，体育馆开放 |
| 晚上 | 上晚课/自习 | 教学楼/图书馆活跃 |
| 深夜 | 回宿舍休息 | 宿舍楼为主，其他关闭 |

每个建筑有独立的开放/关闭时间配置。

### 3.3 时间循环节奏

- **日**：最小循环单元，每天学生按时段活动
- **周**：每周可轮换食堂菜单，做管理决策
- **学期**：学期末结算，根据绩效发放下学期预算并评级

## 四、校园地图

### 4.1 地图设计

- 大型校园，10+ 栋宿舍楼、5+ 个食堂、多栋教学楼
- 固定布局（非自由建造型）
- 学生在地图上实时移动，可被玩家观察到
- 像素风瓦片，统一分辨率

### 4.2 UI 设计

- 主界面为地图，侧边栏显示配置面板和数据看板
- 可折叠的分级显示：默认简洁，展开可看详细数据
- 数据展示包含：实时仪表盘、历史趋势图表、事件日志/新闻滚播、预警系统

## 五、核心系统

### 5.1 食堂管理系统

#### 5.1.1 管理颗粒度

窗口级管理。每个食堂有多个窗口，每个窗口独立配置。

#### 5.1.2 菜品系统

- **预设菜品库**：几十种预设菜品，每道菜有固定的成本、质量、口味属性
- **食堂专属菜单**：每个食堂有自己的菜单范围（如清真食堂只有清真菜品）
- **每周轮换**：每周可更换菜品，频繁更换可能降低满意度（喜欢的菜没了）

#### 5.1.3 定价

- 混合模式：每道菜可单独定价，也可按窗口统一设加成率
- 学生消费模式：一菜一饭（每顿买一个菜 + 米饭）

#### 5.1.4 排队

- 实时排队模拟，窗口排队过长影响学生选择
- 服务速度受厨师技能等级影响

#### 5.1.5 升级

- 有升级周期：需要材料和工程师，施工期间该窗口/食堂停用
- 升级提升质量上限、服务速度、环境评分等

### 5.2 宿舍管理系统

#### 5.2.1 管理方式

参数配置型，用滑块调参。

#### 5.2.2 配置项（独立成本项）

| 参数 | 影响 |
|------|------|
| 热水供应时段 | 时段长 → 满意度↑ 成本↑ |
| 电费定价 | 定价高 → 学生不满 成本回收↑ |
| 维修频率 | 频率高 → 设施好 → 满意度↑ 成本↑ |
| 门禁时间 | 严格 → 满意度↓ 安全满意度↑ |
| 清洁等级 | 等级高 → 满意度↑ 成本↑ |

#### 5.2.3 宿舍等级差异

不同宿舍楼有不同等级：有空调/无空调、独卫/公共卫浴等，影响满意度和建造成本。

## 六、学生系统

### 6.1 学生模型

个体模拟（类似《天际线》市民），用概率分布批量生成。

### 6.2 学生属性

| 属性 | 说明 |
|------|------|
| 姓名 | 随机生成中文姓名 |
| 钱包余额 | 每月生活费，花完只能选最便宜的 |
| 口味偏好 | 基于地域（辣/清淡/甜等） |
| 性格标签 | 吃货/学霸/抠门/运动健将等，影响行为优先级 |
| 满意度 | 0-100 分，受每次就餐/住宿体验影响 |
| 位置 | 地图上的实时坐标 |
| 时间表 | 按照上课/吃饭/休息的时段自动移动 |

### 6.3 学生行为

- 到饭点自动去食堂吃饭（早晨/中午/傍晚）
- 上课时间去教学楼
- 深夜回宿舍
- 路径上实时可见

### 6.4 学生选择模型（多因素效用模型）

```
效用 = w1×口味匹配 + w2×(1/价格) + w3×(1/距离) + w4×(1/排队长度) + w5×质量
```

学生选择效用最高的窗口。效用低于阈值则放弃就餐（满意度下降）。

### 6.5 学生流失

学生不会因满意度低而离开，但满意度持续降低最终会触发游戏结束。

## 七、经济系统

### 7.1 收入来源

- 学校拨付预算（按绩效挂钩）
- 食堂营收
- 宿舍水电费收入

### 7.2 支出项目

- 员工工资（厨师、维修工、保洁、宿管等）
- 食材采购成本
- 能源费用（水、电、燃气）
- 维修费用
- 建筑升级费用

### 7.3 预算机制

**绩效挂钩制**：上一学期经营好（满意度高、利润达标），下学期预算增加，形成正向循环。

### 7.4 物价模型

基础成本固定不变，但随机事件可能临时冲击某项成本（如食材涨价、能源涨价）。

## 八、员工系统

- 员工自动配齐，无需招聘管理
- 可花钱培训员工，提高技能等级
- 技能等级影响服务质量和效率（如厨师技能→菜品质量↑ 服务速度↑）

## 九、满意度系统

### 9.1 计算公式

```
总满意度 = 食堂满意度×30% + 宿舍满意度×30% + 教学环境×20% + 文娱×20%
```

### 9.2 数值范围

0-100 百分制。

### 9.3 失败条件

总满意度低于 60 分 → 游戏结束。

## 十、声望系统

- 学校声望随经营表现上升/下降
- 声望影响：招生质量（更好的学生群体）、预算额度

## 十一、评级系统

每学期结束时给出评级：S / A / B / C / F。

- S 级：满意度 85+ 且利润达标
- F 级：满意度低于 60 或利润严重不达标 → 游戏结束

## 十二、难度设置

三档难度：简单 / 普通 / 困难。

影响：初始预算、学生宽容度、事件频率、绩效系数。

## 十三、随机事件

| 类型 | 示例 |
|------|------|
| 检查/投诉 | 卫生检查、物价局检查、学生投诉上新闻 |
| 设备故障 | 管道漏水、停电、热水器损坏 |
| 周期性事件 | 开学季、考试周、毕业季、校运会 |
| 物价冲击 | 食材涨价、能源费用临时上调 |

## 十四、存档系统

多存档位，支持不同策略的存档对比。

## 十五、新手引导

按需提示系统，玩家可随时点击"提示"按钮查看当前可做的操作和优化建议，不强制教程。

## 十六、MVP 范围与扩展计划

### MVP（第一版）

- 校园地图（固定布局、学生实时移动）
- 食堂管理系统（窗口级、菜品库、排队、定价）
- 宿舍管理系统（参数配置、等级差异、门禁）
- 满意度 + 经济核心循环
- 数值系统完整实现

### 后续扩展

- 快递驿站
- 体育场馆
- 校园交通系统
- 校医院
- 更多随机事件
- 更多菜品和食堂类型
- 多周目继承
